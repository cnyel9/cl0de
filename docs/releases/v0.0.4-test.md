Cl0de 0.0.4 test adalah build uji, bukan rilis resmi. Isinya satu hal: provider baru bernama MiMo.

## Isi build uji

- Provider MiMo: empat model chat Xiaomi MiMo Studio masuk picker sebagai provider "MiMo", tepat sesudah Deep: MiMo V2.6 Pro, MiMo V2.6 Flash, MiMo V2.5 Pro, dan MiMo V2.5, semuanya berlabel "(Chat)". Di baliknya ada bridge lokal baru (Node.js, port 8182, proses terpisah dari bridge Deep) yang membungkus modul MiMo Studio pihak ketiga yang dibundel utuh tanpa diubah, persis pola provider Deep. Modul itu hanya menerima satu prompt per giliran plus id percakapan, jadi bridge memetakan sesi OpenCode ke percakapan server MiMo: giliran pertama melipat system prompt dan pesan pertama menjadi satu prompt, giliran berikutnya hanya mengirim pesan terakhir dengan id percakapan tersimpan, dan id percakapan yang mati dicoba ulang satu kali sebagai percakapan baru. Reasoning yang dikembalikan layanan dipetakan ke reasoning_content, jadi tampil seperti model berpikir lain.
- MiMo adalah chat saja, sama seperti Deep: tidak ada tool (sesi MiMo berjalan dengan agen ringan "mimo" sendiri, tanpa alat), tidak ada gambar sama sekali (model didaftarkan tanpa lampiran dan modalitas teks saja, karena modulnya memang tidak punya jalur gambar), dan banner info di chat kini juga tampil untuk MiMo dengan teksnya sendiri. Web search MiMo tidak dinyalakan (di spike terbukti jalan tetapi lambat sekali, 78 detik).
- Semua pemasangan langsung bisa memakai MiMo tanpa login apa pun: cookie sesi MiMo Studio ditanam ke APK saat build dari secret repo (di repo hanya ada berkas placeholder sentinel; langkah build di kedua workflow menggagalkan build bila secret kosong, berkas hasil decode kosong, tidak memuat nama kunci ph, atau masih placeholder). Cookie tidak pernah masuk config OpenCode atau prefs. Default pasang baru TIDAK berubah: tetap model Deep.
- Keamanan jalur cookie: direktori staging bridge ditambahkan ke daftar pengecualian Backup (cookie hasil staging tidak ikut arsip backup di folder Download publik; staging selalu diulang dari aset saat bridge menyala). Bridge MiMo menyensor semua log dan pesan error keluarnya (nilai cookie dan parameter ph disamarkan, tidak ada URL yang dicatat), dan pola sensor yang sama ditambahkan ke pembersih log laporan bug. Staging cookie di perangkat menolak berkas kosong, placeholder, atau berkas tanpa nama kunci ph dengan status gagal yang jelas.
- Supervisi runtime: bridge MiMo diawasi seperti bridge Deep (gerbang port 8182, watchdog dengan backoff sampai 30 detik, tidak dibunuh saat ganti provider atau aplikasi ke latar), berbagi runtime Node.js yang sama (provisioning kini dikunci satu Mutex supaya dua bridge yang pertama kali menyala bersamaan tidak balapan memasang nodejs), dan kini berhenti dengan benar di reset runtime dan saat layanan latar dihancurkan. Peringkat picker: deep 0, mimo 1, opencode-go 2, opencode 3.

Catatan jujur: cookie sesi yang ditanam adalah sesi akun Xiaomi sungguhan dan bisa diekstrak dari APK oleh siapa pun yang mengunduhnya; itu konsekuensi desain "tinggal pakai" yang dipilih sadar, dan cookie itu kedaluwarsa sekitar 16 Desember 2026, sesudah itu MiMo mati di semua pemasangan sampai ada build baru dengan cookie segar. Angka limit konteks keempat model MiMo (128000) adalah asumsi konservatif, bukan angka terverifikasi dari layanan (spike hanya mengukur prompt server sekitar 3.815 token). Percakapan MiMo hidup di server Xiaomi per id percakapan; bila bridge di-restart, petanya kosong dan giliran berikutnya menyemai percakapan baru dari system, pesan pertama, dan pesan terakhir. Build ini berstatus uji; vonis akhirnya ditentukan uji perangkat.

## Pasang

Pasang APK ini menimpa pemasangan sebelumnya, tidak perlu copot pasang, karena sertifikatnya sama dengan release-1. Paket com.cl0de.app, versi 0.0.4 test, versionCode 21. Ukuran dan md5 APK menyusul di catatan rilis GitHub sesudah build selesai, tidak ditulis di berkas ini.
